# 0. REGLA FUNDAMENTAL

NO escribir todo el proyecto de una sola vez.

Trabajar por fases.

Antes de implementar cada fase:

1. analizar arquitectura
2. explicar brevemente qué se va a construir
3. crear/modificar únicamente los archivos necesarios
4. ejecutar pruebas
5. corregir errores
6. verificar que la fase funciona
7. continuar con la siguiente fase

NO dejar pseudocódigo donde se solicita código funcional.

NO utilizar implementaciones ficticias cuando exista una solución real.

NO esconder errores con `any`, `@ts-ignore`, `eslint-disable`, excepciones vacías o hacks.

Si una dependencia no es compatible con Expo/React Native, buscar una alternativa compatible antes de continuar.

# 5. CLIENTES

Un cliente NO necesita usuario y contraseña.

El método de acceso principal será:

```text
Código de activación
```

Ejemplo:

```text
INFITV-3452-JFKR
```

El código será una credencial de activación y NO debe almacenarse en texto plano en la base de datos.

Guardar un hash del código cuando sea posible.

El código debe tener:

* ID
* hash
* prefijo visible
* fecha de creación
* fecha de activación
* fecha de vencimiento
* plan
* estado
* límite de dispositivos
* cliente asociado
* metadata
* última utilización

Estados:

```text
PENDING
ACTIVE
EXPIRED
SUSPENDED
REVOKED
```

# 6. GENERACIÓN DE CÓDIGOS

Crear generador seguro.

Formato:

```text
INFITV-XXXX-XXXX
```

Ejemplo:

```text
INFITV-7K4P-X92M
```

Usar caracteres fáciles de distinguir.

Evitar:

```text
O / 0
I / 1
L / 1
```

Generar códigos criptográficamente aleatorios.

NO utilizar:

```ts
Math.random()
```

para generar credenciales.

# 7. ACTIVACIÓN

Flujo:

```text
APK
 ↓
Usuario introduce código
 ↓
POST /api/v1/auth/activate
 ↓
Backend valida código
 ↓
Verifica vencimiento
 ↓
Verifica estado
 ↓
Verifica límite de dispositivos
 ↓
Registra dispositivo
 ↓
Genera sesión
 ↓
Devuelve access token
```

Respuesta:

```json
{
  "success": true,
  "token": "...",
  "expiresAt": "...",
  "customer": {
    "id": "...",
    "plan": "...",
    "expiresAt": "..."
  }
}
```

La APK debe guardar el token de forma segura.

NO guardar tokens sensibles en AsyncStorage si existe una alternativa segura compatible con Expo.

Utilizar SecureStore para secretos/sesiones.

# 8. VINCULACIÓN DE DISPOSITIVOS

Un código puede tener:

```text
deviceLimit = 1
```

o:

```text
deviceLimit = 2
```

Cuando el primer dispositivo activa el código:

```text
Código
 ↓
Device A
```

Si intenta activar otro:

```text
Código
 ↓
Device B
```

el backend debe rechazarlo si se superó el límite.

Mensaje:

```text
Este código ya alcanzó el límite de dispositivos.
```

Desde el panel administrativo debe ser posible:

* ver dispositivo
* ver última conexión
* revocar dispositivo
* desvincular dispositivo
* cambiar límite
* bloquear dispositivo

NO utilizar únicamente un identificador fácilmente falsificable como mecanismo de seguridad.

Usar una combinación razonable de:

* instalación/app instance ID
* token de dispositivo
* sesión
* metadata
* controles server-side

---

# 9. EXPIRACIÓN

El backend es la autoridad.

La APK NO debe decidir por sí sola si una suscripción está activa.

Cada request autenticada importante debe poder comprobar:

```text
customer.status
customer.expiresAt
session.status
device.status
```

Cuando vence:

```text
ACTIVE
   ↓
EXPIRED
```

La aplicación debe mostrar:

```text
Tu acceso ha vencido.

Contactá al administrador para renovarlo.
```

# 70. REGLA FINAL DE DESARROLLO

No avanzar automáticamente a la siguiente fase si la fase actual no funciona.

Después de cada fase:

1. ejecutar instalación
2. ejecutar typecheck
3. ejecutar lint
4. ejecutar tests
5. verificar imports
6. verificar variables de entorno
7. verificar migraciones
8. revisar errores
9. corregirlos
10. documentar lo realizado

Al finalizar cada fase mostrar:

```text
FASE X COMPLETADA

Archivos creados:
...

Archivos modificados:
...

Dependencias:
...

Comandos ejecutados:
...

Tests:
...

Estado:
PASS / FAIL

Siguiente fase:
...
```

El objetivo no es producir la mayor cantidad de código posible.

El objetivo es producir un sistema **real, mantenible, seguro, funcional y desplegable**.

Prioridad:

```text
1. Correctitud
2. Seguridad
3. Estabilidad
4. Mantenibilidad
5. Rendimiento
6. UX
7. Escalabilidad
```

No sacrificar las primeras prioridades para implementar funcionalidades rápidamente.
